[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/christiantrudeau/coincidence-Shapley-serial/blob/main/notebook/reproduce_results.ipynb)

Code, data and tests for the numerical study (Section 6) of "On the (non-)coincidence of the serial
and Shapley solutions in multi-server queueing and scheduling problems", by Sreoshi Banerjee and
Christian Trudeau.

The study compares the two rules on 78,480 simulated scheduling problems with discretely divisible
jobs. It uses a dynamic program that computes the exact Shapley value in O(n³k) operations.

## Reproducing the results

You need Python with the packages in `requirements.txt` (`pip install -r requirements.txt`). The
results were tested with Python 3.14.7 and those exact versions, which are pinned because numpy does
not guarantee identical random draws across versions.

```
python src/reproduce_all.py
```

This runs the whole study from the seeds, writes to `outputs/`, compares every output with `data/`
and `results/`, and stops with an error if a reported number differs. Rows of the hill-climbing
searches can differ between computers, without affecting any reported number; for these, the check is
the paper's statement that no gap found exceeds half of the bound. See
[`docs/machine_and_run_times.md`](docs/machine_and_run_times.md) for why, and for how long it takes.

To run one step, work from a separate folder, because the scripts read and write in the current folder:

```
mkdir outputs
cd outputs
python ../src/run_grid.py                 # grid_results.csv
python ../src/summarize.py                # summary.json and table3_rows.tex
python ../src/make_fig.py                 # Figure 1
python ../src/adversarial_search.py       # adv_results.json
python ../src/adversarial_search_n16.py   # adv2_results.json
python ../src/pilot_pessimistic.py        # the pilot table, printed
```

Inputs: job lengths must be positive integers (Python or numpy integers), and `k` is a positive
integer. `shapley_opt_div` and `serial_div` refuse anything else.

## Tests

```
python -m unittest discover -s tests            # about a minute and a half
python tests/audit_full_grid.py efficiency      # all 78,480 problems: shares sum to the total cost
python tests/audit_full_grid.py exact           # 1,080 problems in exact rational arithmetic
```

| File | What it checks |
| --- | --- |
| `tests/test_numerical.py` | Exact-arithmetic dynamic program against exact brute force; floating-point code against exact values on grid problems (n up to 50); shares sum to the total cost; the rules coincide when lengths are multiples of k; input checks |
| `tests/test_saved_results.py` | The numbers of Section 6, Table 3 and the data of Figure 1 rebuild from the saved data; a sample of 216 problems recomputes from its seeds |
| `tests/test_sections_2_5.py` | Runs `tests/ejor_rr_checks.py`: 56 checks by brute force, with exact fractions |
| `tests/audit_full_grid.py` | The two slower checks above |
| `tests/compare_results.py` | Compares a full fresh run with the saved study |
| `tests/shapdp_exact.py` | The dynamic program in exact rational arithmetic, used by the tests |

On every change, GitHub runs the tests, and the notebook through its launcher, on Windows, macOS and
Linux. The [Full reproduction](.github/workflows/full-reproduction.yml) workflow reruns the whole
study on all three systems; it can be started from the Actions tab.
